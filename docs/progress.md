# Прогресс

Этап 1 завершён: собственные Lexer/Parser и AST, позиции ошибок, 8 тестов SQL + шаблонный тест прошли на .NET 8. Этап 2 в работе: исполнитель CRUD и агрегатов. SDK установлен в /workspace/tools/dotnet, для команд в облаке добавить его в PATH. Тесты требуют разрешённых локальных IPC.

Этап 2 завершён: CRUD, WHERE/ORDER/LIMIT, COUNT/SUM/AVG/GROUP BY. 12 тестов прошли. Многострочный INSERT и UPDATE атомарны. Следующий этап: страничное бинарное хранение.

Этап 3: бинарный формат страниц 4096, запись не пересекает страницу, UTF-8, схемы и стабильные rowId; размер строки проверяется до сохранения. Вся БД загружается в память; изменения пока сохраняются атомарной заменой образа, WAL будет на этапе 5.

Этап 4 завершён: B-дерево степени 16 с разбиением узлов, bucket для дубликатов, сохранение топологии и ключей в бинарных страницах. EXPLAIN использует тот же выбор плана, что SELECT. Индексный equality-поиск обращается к rowId напрямую; счётчик LastRowsExamined доступен тестам. При изменениях индексы перестраиваются (осознанное ограничение скорости записи).

Этап 5 завершён: протокол описан в docs/wal.md, full-page redo WAL с SHA-256 и commit marker, Flush(true), checkpoint, single-writer lock. BEGIN/COMMIT/ROLLBACK и откат индексов проверены. 23 теста: включая 4 Kill(true) отдельного процесса, оборванный хвост, повторное открытие. В тестовом ожидании исправлена ошибка: после изменения одной из двух строк с age=25 остаётся одна.

Этап 6 завершён: nested-loop JOIN с квалифицированными именами, неоднозначность проверяется; CLI db>, SQL-файлы, UTF-8, помощь/выход. Генератор 100000 строк, BenchmarkDotNet, сценарии защиты Bash и PowerShell, README, architecture, defense, CI Windows/Linux, VS Code tasks.

Итоговая проверка текущего облачного Linux: Release build — 0 warnings/errors; 39 тестов пройдено, 0 пропущено, включая 5 убийств реального дочернего процесса (в том числе частичное тело WAL). Обязательный SQL-пример выполнен. Bash-сценарий защиты повторно прошёл: 100000 строк, seek вместо scan, быстрый замер 643.28x, данные после убийства до COMMIT сохранены в исходном состоянии. BenchmarkDotNet-отчёт: docs/benchmark.md.

Ограничения: всё исполнение в RAM, запись полного бинарного образа страниц, перестройка индексов на каждую команду записи, equality-only индексный SELECT. Эти решения документированы и не скрывают полный перебор внутри seek. На Windows/PowerShell сценарий в данной Linux-среде не запускался (pwsh отсутствует); удалённый GitHub Actions тоже не запускался. Все обязательные этапы реализованы; бонусные функции не добавлялись.
