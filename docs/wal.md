# Протокол WAL (до реализации этапа 5)

Single writer, no-steal: явная транзакция меняет только память. Снимок до BEGIN нужен для ROLLBACK. Неуспешный отдельный SQL восстанавливает состояние до команды, оставляя транзакцию активной.

При COMMIT или autocommit:
1. Полный новый образ страниц сериализуется и проверяется до I/O.
2. В WAL записывается frame: magic 8 байт, длина int64 LE, SHA-256 32 байта, образ страниц. Flush(true).
3. Дописывается маркер COMMIT (8 байт), Flush(true). Это точка подтверждения. Пользователь получает успех только после неё и checkpoint.
4. Checkpoint перезаписывает основной файл, SetLength, Flush(true).
5. WAL обнуляется, Flush(true).

При открытии сначала читаются полные frames WAL, проверяются magic, длина, hash и commit. Подтверждённый полный образ повторно записывается в основной файл и сбрасывается. Неполный/оборванный хвост игнорируется. После успешного checkpoint WAL обнуляется. Повторное восстановление идемпотентно: записывается образ страниц, а не повторяются INSERT.

Процесс может погибнуть после flush маркера, но до ответа пользователю: результат в этом случае подтверждён (обычная неопределённость ответа после COMMIT). До маркера основной файл не меняется. Во время checkpoint целостный образ остаётся в WAL. Гарантии опираются на Flush(true) и файловую систему, честно выполняющую fsync. Защита от произвольной порчи носителя и конкурентный доступ не реализуются; используется эксклюзивная блокировка .lock.
